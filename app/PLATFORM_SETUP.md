
# Flutter platform setup

This repository contains the shared Flutter/Dart application source.

The native `android/`, `linux/`, and `windows/` folders are generated by Flutter for the
installed Flutter SDK version. Generate them in the app directory with:

```bash
flutter create --platforms=android,linux,windows .
```

Then run:

```bash
flutter pub get
flutter run -d linux
```

or:

```bash
flutter run -d windows
```

or:

```bash
flutter run -d <android-device>
```

Keeping generated platform folders SDK-version-specific avoids pinning the repository to
one machine's generated files.

## Phase 9 background transfers

After adding `workmanager` and running `flutter create`, build the Android target normally. NexaDrive schedules a unique 15-minute background worker after login; it only asks the OS to run when network connectivity is available and the battery is not low. The worker resumes the durable upload queue rather than copying files again.

Android background execution is best-effort and controlled by the OS. Long-running foreground-service transfer mode is deliberately not enabled in this phase.

The project currently commits Flutter business logic but can generate platform shells with:

```bash
./scripts/bootstrap-platforms.sh
```
